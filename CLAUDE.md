# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

RoguePlusPlus is a C++ port of the classic PC game "Rogue", based on the PC Rogue 1.48 sources (A.I. Design / Epyx, 1983–84) as ported to Linux/ncurses. The code now compiles as **C++23**, but it is still structured like the original C: free functions over one game state (`game()`), and plain `Creature`/`Item` structs. It is being modernized incrementally into separate modules. The plan, the decisions already made and the progress so far are in **`docs/MODERNIZATION.md`**. Read it before any structural change, and update its "Done" section when a phase step lands.

## Build & run

Requirements: CMake ≥ 4.0, a C++23 compiler (GCC 15 is used), pkg-config, and ncursesw. nlohmann/json 3.12 is used if installed, otherwise fetched.

```sh
cmake -S . -B build             # first configure fetches nlohmann/json and GoogleTest (ROGUE_BUILD_TESTS=OFF skips GoogleTest)
cmake -S . -B build-chk -DROGUE_DEBUG_CHECKS=ON   # with the consistency checks; -DROGUE_ASCII=ON draws ASCII
cmake --build build
ctest --test-dir build          # all unit tests
./build/rogue_tests --gtest_filter='Dice.*'   # a single suite or test
./build/rogue++                 # new game
./build/rogue++ -d 4242         # reproducible dungeon from a seed (`v` in game shows the seed)
./build/rogue++ -s              # show scores
./build/rogue++ -r              # restore the game saved with S
```

Targets: `rogue_game` is a static library built from every `src/**/*.cpp` except `src/app/`. `rogue++` links `src/app/main.cpp` against it. `rogue_tests` builds from `tests/**/*.cpp`, and tests may include any game header. Sources are globbed with `CONFIGURE_DEPENDS`. All targets use `-Wall -Wextra -Wpedantic` and **must stay warning-free**.

Smoke test without a real terminal: `tmux new-session -d -s rg -x 80 -y 25 ./build/rogue++`, then `tmux send-keys -t rg ...` and `tmux capture-pane -p -t rg`. The game needs an 80×25 screen. After the name prompt, wait about 2.5 s for the curtain animation to finish.

To check that a change leaves the game unchanged, use the replay scripts in `tools/replay/` (see its README). `make-trees.sh` builds `main`, the working tree and an ASan/UBSan build; `replay.py` plays the same seeded keys on each and compares every screen; `classify.py` separates timing noise from divergence; `resume.py` checks save and restore.

At runtime the game reads `rogue.opt` (options) and writes `rogue.scr` (scores, JSON; an old binary one is read and rewritten as JSON) in the current working directory. `S` saves the game (JSON, default `rogue.sav`, the `savefile` option) and exits; `./build/rogue++ -r` (or `rogue++ <file>`) restores it and deletes the file.

## Conventions

- New code goes in `namespace rogue`, in `.hpp`/`.cpp` files under a module directory (`src/core/`, …), and is included as `"core/Random.hpp"`. `src/` is on the include path only for quoted includes (`-iquote`), so project headers never hide system headers.
- No source file defines a macro (phase 10): constants are `constexpr`, build switches are `rogue::config` constants, and the one feature macro a system header needs (`NCURSES_WIDECHAR`) is a compile definition in `CMakeLists.txt`. Keep it that way. Use `true`/`false` and `nullptr`. `<curses.h>` itself defines lowercase macros (`clear`, `move`, …), but only `ui/curses/CursesTerminal.cpp` includes it; that's why `Flags` has `unset()` rather than `clear()`.
- All randomness goes through `rogue::rng()` (the game's `game().random`, or the `rnd()`/`roll()` wrappers). Never use `rand()` or the clock, or seeds stop reproducing.
- Keep string handling `const`-correct. Fixed text (the tables of names, looks and help, phase 11.1) is `std::string_view`; a `string_view` is never null, so an optional name is `std::optional<std::string_view>`. Text the game changes is `std::string` (options, the message line, scroll titles and guesses, the macro's typeahead; 11.2), and `input().read_line()` returns one (`nullopt` for Escape). Damage is `Attacks` (11.3). Characters are tested and case-converted with `core/Ascii.hpp` (`is_alpha()`, `to_upper()`, ...: ASCII only, whatever the locale), never `<cctype>`. Text is never passed as `const char *`: parameters take `std::string_view` (11.5), and an optional one is `std::optional<std::string_view>`. New text is built as `std::string` with `std::format` (include `<format>` before the legacy headers; `rogue.h` does); `msg()`, `addmsg()`, `ifterse()` and `fatal()` take a `std::format` string checked at compile time (`msg("the {} misses", name)`), so a format kept in a variable must be `constexpr`, text chosen at run time goes through `"{}"`, and a `char` or `unsigned char` meant as a letter needs `{:c}` (the default prints `unsigned char` as a number). An empty `msg()` clears the message line.
- No raw pointers to game things (phase 12). A creature, item or room that is always there is passed as a reference (`Item &`); one that may be missing is a `rogue::Maybe<T>` (`core/Maybe.hpp`: shaped like C++26's `std::optional<T &>`, tested as a bool, read with `*`/`->`, but compared by identity; `refers_to(m, thing)` asks whether it names that thing); a table with its length is a `std::span`. A stored link is a handle (`ItemId`, `CreatureId`, `RoomRef`). Pointers remain only inside the pool (`Slots`, `talloc()`, `ListPool::at()`) and at system APIs.

## Architecture (current, pre-modularization)

- **Core types** (`src/core/`): `Random`, `Coord` (the legacy `coord` is an alias), `Dice` and `Attacks` (`core/Dice.hpp`: damage, up to four `Dice`; a literal such as `"1d2/1d5"` converts at compile time, so a malformed one does not compile, and text read at run time goes through `Attacks::parse()`), `Flags<E>`, a bitset for opted-in enums (`RoomFlag`/`RoomFlags` so far), and `KindTable<E, T>`, an array indexed by a kind enum. The kinds are `Potion`, `Scroll`, `Ring`, `Stick`, `WeaponType`, `ArmorType`, `Food` and `Hand` (`items/Kinds.hpp`), `Trap` (`world/Trap.hpp`) and `rules::SaveThrow`; each has its `kind_count<E>`. A square's map flags are `MapFlags` (`world/MapFlags.hpp`): `MapFlag` bits plus its passage number or trap kind. An item's kind number `o_which` is read with `which<E>()` and written with `set_which()`.
- **Game state** (`src/game/`): `rogue::Game`, reached through `game()`, holds everything that used to be a global game variable. Its members are `random`, `pool` (creatures and items, owned by numbered `Slots` of `std::unique_ptr` and sharing one count of `MAXITEMS`; `discard()` frees at once, so never read a thing after discarding it), `options` (`rogue.opt`), `message` (the message line), `turn` (the command being carried out), `player`, `level` (map, rooms, floor objects, monsters), `items` (odds, looks, what is known), `scheduler` (daemon and fuse slots), `playing` and `noscore`. The rogue himself is `game().player.body` (a `Creature`: `t_pos`, `t_stats`, `t_pack`, `t_room`), and `Level::at()`/`flags_at()` give a square's glyph and `MapFlags`. Functions that use a group bind a local reference after their declarations (`rogue::Player &player = game().player;`, `rogue::Level &level = game().level;`). `Game.hpp` is included by `rogue.h` after the legacy types; include `rogue.h`.
- **Headers**:
  - `rogue.h`: game constants, structs and prototypes. It includes `entities/Creature.hpp` and `entities/Item.hpp` (the split of the old `union thing`, with `CreatureFlags`/`ItemFlags` and `ItemKind`), then `game/Game.hpp`. Lists of creatures and items are `rogue::List<T>` (`entities/List.hpp`); walk them with a range-for, or, when the body may take the entry out, with `first()`/`after()`, which give a `Maybe<T>` that is empty for a detached entry, as the old links were null.
  - The fixed tables live with the module that uses them: the kinds of item (`items::KindInfo`: the `*_base` odds that each game copies, `things_base`) and the weapon and armor tables in `items/ItemCatalog`, `monsters` (`entities::MonsterKind`) in `entities/MonsterCatalog`, the help tables (`HelpLine`) in `game/Help`, and `e_levels` and the ranks `he_man` in `rules/Experience.hpp`. `rogue.h` keeps a few common strings.
- **UI layer** (`src/ui/`): game code talks only to two interfaces, both reachable through `rogue.h`:
  - `display()` (`ui/Display.hpp`): the message line, status and clock, map tiles (`draw_tile`/`tile_at` with a `TileStyle`), pages (`open_page`/`write_at` with an `Ink`), and the title, tombstone, score and winner screens.
  - `input()` (`ui/Input.hpp`): `read_key` (characters or `ui::key` values) and `read_line`.
  - Implementations: `ScreenDisplay` and `ScreenInput` work on `ui::Screen`, an 80×25 grid of cells (glyph code + `ui::Style`). Reads such as `tile_at` come from this grid. `ScreenDisplay` owns layout and colour policy (styles per `Ink`/`TileStyle`, glyph colours, monochrome). `ui::Terminal` is the backend interface, implemented by `ui/curses/CursesTerminal.cpp`, the only file that includes the system `<curses.h>`. That file also holds `ui::start_terminal()`/`stop_terminal()`.
  - `glyphs.h` has the glyph codes (CP437 bytes), key constants and string/screen sizes shared by game and UI. Item kinds are `ItemKind` (`entities/Item.hpp`); `glyph_of()`/`kind_of_glyph()` convert between a kind and its map glyph. **Game files must not draw or read the terminal any other way, and must never include `<curses.h>`.**
- **Platform layer** (`src/platform/`): `Clock` gives the time (`now()`, `local_time()`, `std::chrono` values), and `Session` starts the terminal and holds the ways out, `fatal()` (a `std::format` string, printed after the terminal closes) and `md_exit()`. The special keys become command characters in `ui::command_char()` (`ui/Keys`), and `readchar()`/`flush_type()` (the macro's typeahead, the clock while waiting) are `game/Keyboard`.
- **Game loop**: `app/main.cpp` parses arguments, seeds `rng()`, and sets up the game with `init_*()` (`game/NewGame`: the first pack, and this game's odds and looks of the kinds of item) → `new_level()`, then starts daemons and fuses (`rules/Scheduler` keeps `rules::Event` slots in `game().scheduler` and `fire()` maps each event to its function; `rules/Daemons` holds the callbacks `doctor`/`stomach`/`swander`/…). `playit()` (`game/GameLoop`, with `quit()`) loops over `command()` in `game/CommandDispatcher.cpp`, which reads a key, looks up its `Command` (`game/Command.hpp`: the key table, which commands use up a turn and which a count repeats) and switches on it. Combat is in `rules/Combat`, making monsters in `entities/MonsterCatalog`, monster movement (chasing, slimes) in `entities/MonsterAI`, rooms at play time (entering/leaving, `roomin`, `cansee`, `diag_ok`) in `world/Rooms`, the map's squares (`INDEX`, `offmap`, `winat`, `step_ok`, `find_obj`) in `world/Map`, the rogue's glance and search in `world/Look`, traps (`be_trapped`, `descend`, `tr_name`) in `world/Traps`, and level generation in `world/LevelGenerator` (with `world/Passages` and `world/Maze`). The rogue's moves (`do_move`, `do_run`, `rndmove`) are `game/Movement`. The message line and its prompts (`msg()`, `more()`, `wait_msg()`, ...) are `game/Messages`, the status line and clock `game/StatusLine`. Eating is `rules/Hunger`, strength `rules/Strength`, the help screens `game/Help`, and the direction prompt, the stairs and the macro `game/PlayerCommands`. Taking things from the pool and giving them back (`new_item()`, `discard()`) is `game/Pool`, dying, winning and the score list `game/Endings`, and the items are `items/` (catalog, identification, inventory, and per-kind effects in `items/effects/`).
- **Persistence** (`src/persistence/`): `OptionsFile` reads `rogue.opt` into `game().options` (`parse_options`/`apply_option`/`load_options`). `HighScores` reads and writes the score file (`load_scores`/`save_scores`, JSON through nlohmann/json, which only this module includes); `game/Endings` keeps the top-ten logic (`add_score()`) and the score screen. `SaveGame` writes all of `Game` plus the screen's map (`MapView`) as JSON and loads it back, checked with `pool_problems()`; it has `static_assert`s on the struct sizes, so a new field in `Game` must be saved; `SaveCommands` has the `S` command (`save_game()`) and `restore()`.
- **Testing the UI headlessly**: `tests/ui/` drives `Screen`, `ScreenDisplay` and `ScreenInput` with fake `Terminal`s.

## Build switches

The CMake options `ROGUE_DEBUG_CHECKS` (consistency checks that report with `debug()` messages, and "Exited normally" at the end) and `ROGUE_ASCII` (ASCII instead of Unicode glyphs), both off by default, become `rogue::config::debug_checks` and `rogue::config::ascii_glyphs` in the generated `core/Config.hpp` (template `src/core/Config.hpp.in`). Code tests them with `if constexpr`, never `#ifdef`, so every build compiles both branches and warns about both. A check must not fire in normal play: replay a checks build against a default one (`tools/replay/`).
